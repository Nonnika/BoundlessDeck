# BoundlessDeck 产品需求 v0.3（agent 驱动）

> 术语：deck 里的所有元素（笔记、文件、终端……）统一叫 **block**。
> 面向创作者与学生的 agent 工作台。画布是工作产物，agent 是工位上的同事，聊天只是控制通道。
> 本文只谈产品需求与取舍；技术落地见 [requirements.md](requirements.md)（v0.2 native 架构）。

## 0. 一句话定位与核心断言

**说一句话，画布上长出可以改、可以扔、可以交的东西。**

四条断言，后面所有需求都从它们推出来：

1. **聊天是控制通道，画布是产物。** 聊天记录可以丢，画布不能。每次 agent 的产出都必须落在具体卡片上，并带来源。
2. **选择即上下文。** 人框选三张卡片说"按这个风格来"，比 attach 三个文件自然。反向也成立：agent 要能"指着"某张卡片提问。
3. **先预览后落地。** agent 的写操作先以幽灵形态出现在画布上，人接受/改写/丢弃，或按策略自动接受。这是"敢让它动手"的前提。
4. **一切可回退到某一步。** 撤销粒度是 run 的 step，不只是单次操作。学生要能"回到第 3 步换个思路"，创作者要能"回到昨天那版"。

## 1. 用户与场景

| | 创作者 | 学生 |
|---|---|---|
| 典型人 | 独立作者、编剧、设计/动效、独立开发者、内容博主 | 高中到研究生，理工与人文都有 |
| 一句话任务 | "把这个选题做成能拍的分镜" / "把这段代码变成一个能跑的原型" | "帮我把这一章学明白，然后考我" |
| 输入 | 素材（参考图、链接、视频、脚本、品牌规范） | 教材 PDF、课件、题目照片、课堂笔记 |
| 中间产物 | 大纲、脚本、分镜表、风格板、版本 A/B | 知识地图、例题拆解、错题本、闪卡、模拟卷 |
| 交付 | 成稿/成片素材包/可分享的只读画布 | 作业（要过程）、复习卡组、自测成绩 |
| 最怕 | agent 把稿子改乱了、风格跑偏、素材版权说不清 | agent 直接给答案、自己没学会；隐私（作业/学校材料外泄） |
| 成功感 | 一屏能看完整条产线，改哪张都清楚 | 一步步被带着走，最后自己能复述 |

**两个模式，一套内核。** 学生模式与创作者模式不是皮肤，是两组默认值：

| 维度 | 创作者模式 | 学生模式 |
|---|---|---|
| 默认输出 | 成稿 + 2–3 个变体，允许大改 | 台阶式提示，先问再答，默认不给最终答案 |
| 介入强度 | 低（放开手，批量接受） | 高（每步确认，要求先自己试） |
| 默认卡片 | 脚本、分镜、风格板、版本对比 | 知识地图、例题、闪卡、测验 |
| 安全默认 | 允许写素材目录，禁跑危险命令 | 默认禁写盘、禁联网、禁 shell；导出前提示 |
| 导出契约 | 分辨率/码率/字数/字体清单 | 过程 + 答案分离，附知识点覆盖表 |

## 2. Agent 在画布上的角色模型

一个 run 里可以有多个角色步骤，但 v1 只有**一个 run 在画布上动手**（多进程抢画布是 v2 的事，见 §9）。

| 角色 | 权限 | 典型动作 |
|---|---|---|
| 执行者 Operator | 建/改/移/连/删卡片 | 铺大纲、拆分镜、写脚本、改代码、跑命令 |
| 助手 Assistant | 只在指定卡片内产出内容 | 在选中的卡片里改写、扩写、翻译、重构 |
| 观察者 Critic | 只读，只写批注 | 指出分镜缺镜头、代码有 bug、答案有漏洞、给评分 |
| 检索员 Researcher | 只读素材库/网络（受策略约束） | 找参考、查资料、对答案、抓要点 |

权限是**画布级 + 目录级 + 工具级**三层的交集，不是一句话"允许 agent"。

## 3. Agent ↔ 画布：需要一套显式的画布操作协议

这是整个产品的技术核心：agent 的每个动作 = 一次**带来源的事务**，而不是一串随机 DOM 操作。

| 类别 | 操作 | 说明 |
|---|---|---|
| 读 | `read_selection` / `read_card` / `read_region(bbox)` / `search_cards` | 选择集与视口是上下文边界 |
| 写 | `create_cards` / `update_card` / `move_cards` / `group` / `link` / `delete_cards` | 全部进事务、可撤销、可 diff |
| 指 | `focus(card)` / `highlight(card, reason)` / `annotate(card, note)` | agent 反过来给人提示 |
| 动作面 | `read_file` / `write_file` / `run_command` / `run_code` / `open_url` | 就是上一版的三条主线：素材面、构造面、执行面 |
| 问人 | `ask(question, options)` / `request_approval(action)` | 卡在那里等人，不猜 |

**每次写操作必须带 provenance**：`{runId, stepId, role, prompt, sources[], confidence}`。带来的能力：

- 卡片角标显示"agent 生成 · 来源 3 个素材 · 未审"；
- 一键"回到这步之前"；
- 统计"agent 产出被保留率"（产品最重要的指标，见 §10）；
- 学生场景里，老师/家长可看"哪部分是 AI 写的"。

## 4. 卡片类型（决定产品像不像样）

| 卡片 | 用途 | 优先级 |
|---|---|---|
| 文本 / Markdown | 草稿、笔记、讲义 | P0 |
| 文件预览（已有） | 素材、教材、参考代码 | P0 |
| 代码（已有骨架） | 原型、作业代码、脚本 | P0 |
| 终端（已有） | 跑起来、装依赖、验证 | P0 |
| 图片 / 参考板 | 风格板、分镜图、题目照片 | P0 |
| 大纲 / 树 | 章节、剧本结构、知识地图 | P1 |
| 表格 | 分镜表、对照表、错题表 | P1 |
| 闪卡 / 测验 | 间隔重复、选择题/填空/自评 | P1（学生核心） |
| 版本对比 | A/B 两版并排 diff | P1（创作者核心） |
| PDF 页 | 教材页标注 | P2 |
| 公式（LaTeX） | 理工科 | P2 |
| 时间线 | 视频节奏、历史脉络 | P2 |
| 网页剪藏 | 参考、资料 | P2（且必须按不可信处理，见 §7） |

## 5. 人的介入：三种闸门

| 闸门 | 规则 | 默认 |
|---|---|---|
| 幽灵预览 | agent 的写入先显示为虚线/半透明，Enter 或点击接受；批量接受按 run | 开（可关） |
| 审批 | 写磁盘、跑命令、联网、花钱的 API、发邮件 → 弹审批，可"本次/本目录/本会话"记住 | 学生模式全开；创作者模式按目录 |
| 接管 | 人正在编辑的卡片上锁，agent 不得写；人一动手，该卡片上的 agent 步骤自动暂停 | 开 |

还有一条容易被忽略但必须有：**人来打断**。长 run 必须能随时暂停/改需求/换方向，而不是等它跑完 40 步。

## 6. Run / Step / 成本

- 一个 **Run** = 一个目标（"把这篇 3000 字文章做成分镜"），含若干 **Step**。
- 每个 Step 有：动作、影响的卡片、耗时、token、成本、是否需审批。
- 面板用**人话**展示，不展示原始思维链：`第 4 步 · 拆成 12 个镜头 · 改了 12 张卡 · ¥0.18`。
- 步级回滚；run 级预算上限（学生默认 ¥1/次，创作者 ¥5/次），超限暂停问人。
- 失败重试与"降级完成"（模型挂了 → 用本地模型只做摘要，标注"降级"）。

## 7. 安全与信任（这个产品最容易被低估的部分）

agent 有文件写、shell、网络三把钥匙，同时会读入不可信内容（网页、PDF、别人发的作业）。

| 编号 | 需求 |
|---|---|
| S-1 | **不可信内容标记**：剪藏网页、PDF、图片 OCR 文本进入上下文时打 `untrusted` 标；来自 untrusted 的"指令"不能直接触发写文件/跑命令，必须人工批准 |
| S-2 | 目录白名单：读、写分别授权，工作区外的路径默认拒绝，写入前显示 diff |
| S-3 | 命令策略：默认禁 `rm -rf /`、`curl \| sh`、`sudo`、读密钥目录；可加白名单 |
| S-4 | 密钥保管：API key 存 `mygo.Secrets`（系统钥匙串），**永不进 prompt、永不进画布** |
| S-5 | 本地优先：支持本地模型端点（Ollama 等）；云端调用默认不带文件全文，只带必要片段 |
| S-6 | 审计：完整 run 日志（谁、何时、改了哪张卡、基于什么），本地保存，可导出 |
| S-7 | 学生保护：默认不代写整篇作业；"作业模式"产出过程+答案分离；家长/老师视图（v2） |
| S-8 | 导出前检查：未审的 agent 卡片、未标注来源的素材、敏感信息残留 |

## 8. 双向 MCP：一个容易被忽略的产品机会

目标用户已经在用 Claude Code / ChatGPT / Cursor。所以除了应用内置 agent，还要：

1. **内置 agent 可用 MCP 工具**（联网检索、GitHub、Notion、本地工具）；
2. **应用本身作为 MCP server**：把 `create_cards / update_card / run_command / read_selection` 暴露出去，让用户自己的 agent 直接驱动这块画布。

第 2 条几乎是白送的差异化：别人的 agent 只能改文件，你的 agent 能改一块**看得见的画布**。代价是必须先把 §3 的操作协议做干净——它同时服务内置 agent 和外部 agent。

### 8.1 已实现（v0.4）

全局装一次，任何文件夹里的 agent 都能接入当前图版：

- **端点**：`<root>/.boundlessdeck/mcp.sock` 上的 JSON-RPC（Streamable HTTP 语义，POST `/mcp`，token 校验，socket 0600）。路径过长或平台没有 Unix socket 时退到 `/tmp` 或 `127.0.0.1` 端口。
- **全局安装（默认路径）**：设置窗口（macOS：BoundlessDeck → 设置…，⌘,；Windows/Linux：文件 → 设置…，Ctrl+,）把 `boundlessdeck mcp-stdio`（不带 `--workspace`）合并进 Claude Code（`~/.claude.json`）、Claude 桌面版、Cursor（`~/.cursor/mcp.json`）、VS Code（用户级 `mcp.json`）的用户级配置，可安装、卸载，或在指向另一份 App 时改为当前这份。只改我们这一项，保留文件权限；读不了的配置原样不动。`go run`/`go test` 的临时程序和 macOS 临时位置（AppTranslocation）下的 App 不允许安装。
- **跟随当前图版**：打开图版时 App 把端点写进用户配置目录的 `BoundlessDeck/active-deck.json`（0600，`os.UserConfigDir`，不依赖 App 名，dev 版与打包版共用），关闭时清掉。不带 `--workspace` 的桥每次连不上或 token 失效都重读它，所以切换图版不用重启 agent。App 没开或没打开图版时，桥自己回答 `initialize`、`tools/list` 等（与 App 同一张表），调用工具返回「先在应用里打开一个文件夹」，agent 不会因为先启动而把 server 标成失败。
- **项目级配置（可选，默认关）**：打开工作区总会写 `.boundlessdeck/mcp.json`（端点、token、tool 列表、项目 server 清单）与 `.boundlessdeck/block-schema.json`。设置里打开「打开文件夹时写入项目级 MCP 配置」后，才把同一个 server（`--workspace DIR`）合并进 `.mcp.json`（Claude Code）、`.cursor/mcp.json`、`.vscode/mcp.json`；用户已有的 server 和 key 原样保留，坏 JSON 先备份成 `.bak`。默认关闭，因为文件夹常是代码仓库。设置里可从当前图版的文件夹移除这些配置：只删我们这一项，只剩我们时连文件（和空的 `.cursor/`、`.vscode/`）一起删。
- **stdio 桥**：`boundlessdeck mcp-stdio [--workspace DIR]`，把 newline-delimited JSON-RPC 转发到 socket；连不上时回 JSON-RPC 错误或工具错误结果，不会挂住。排障用 `--check`。
- **工具面**：`deck_info`、`block_schema`、`list_blocks`、`get_block`、`read_selection`、`create_block`、`update_block`、`update_blocks`、`delete_blocks`、`move_blocks`、`select_blocks`、`undo`、`redo`、`save_deck`。
- **排版**：`align_blocks`（边/中线，可对齐到某个 block，`spacing` 顺手排成列）、`distribute_blocks`（等间隙/等中心距，首尾不动，挤不下要显式允许重叠）、`arrange_blocks`（行/列/网格，列宽行高取最大，保持各 block 大小）。省略 `ids` 时用选择集；移动与排版作为一次 `changeMoves` 进撤销栈，⌘Z 一次退回。
- **每个 block 的可写项**：`mcpschema.go` 一张表列全——note 的 `text`，file 的 `path`/`page`，browser 的 `url`，所有 kind 的 `title`/`named`/`x`/`y`/`w`/`h`；其余字段（`id`、`kind`、terminal 的 `term`）只读。表生成工具的 inputSchema，反射测试保证 `block` 新字段必须登记。
- **同一条路径**：写操作走 `addBlock`/`removeBlock`，移动与排版走 `applyPlacements`，与窗口共用撤销栈（加、删、移动、排版）、选择集、`freeSpot` 和原子保存；批量写先整体校验，有一个字段不合法就一个都不写。
- **资源**：`boundlessdeck://deck`、`//blocks`、`//blocks/{id}`、`//schema`。
- **可见性**：窗口状态栏显示 `MCP · N 个工具`，tooltip 给出 socket、配置文件和项目 server；写操作会让画布立即重绘并落盘（UI 线程 marshal、goroutine 写、只写最新快照）。

## 9. 多 agent（明确降级到 v2）

v1 不做"多个 agent 抢同一块画布"。v1 的"多角色"是一个 run 内部的角色切换（研究者→写手→批评者），共享同一条 step 链。真多 agent 需要：黑板/消息总线、卡片租约、冲突合并、预算分配，成本高、演示价值大于使用价值。

## 10. 验收：v1 的闭环与指标

**唯一验收脚本**（两条都要跑通，一条创作者一条学生）：

> 创作者：空画布 → "我想做一期 8 分钟讲'为什么城市里没有萤火虫'的视频" → agent 铺出 6 张卡（选题角度 / 大纲 / 脚本片段 / 分镜表 / 3 张参考图 / 待办）→ 人删 1 张、改 1 张、框选 2 张说"按这个调子重写脚本" → 导出成稿。
>
> 学生：拖入一章 PDF → "先帮我理清这章的逻辑，别给答案" → agent 出知识地图 + 3 个引导问题 → 人答错一题 → agent 指出误区并出一道同类题 → 生成 8 张闪卡。

| 指标 | 目标 |
|---|---|
| 首价值时间（空画布 → 第一张有用卡片） | ≤ 60s |
| agent 产出保留率（24h 后仍在画布上且未被大改） | ≥ 60% |
| 每轮人工编辑步数（越少越好，但不能为 0） | 1–4 |
| 回退率（回滚到某步的比例） | ≤ 15% |
| 单任务成本 | 学生 ≤ ¥0.5，创作者 ≤ ¥2 |
| 画布性能（200 卡 + 3 终端 + agent 流式写入） | ≥ 55fps，不卡输入 |

## 11. v1 范围

做：画布内核（已具备）、文件/代码/终端三面（已具备）+ markdown/图片、单 agent 单 run、幽灵预览 + 审批 + step 回滚、provenance、run 面板、学生/创作者两套默认策略、导出 PDF/Markdown。

不做：多人实时协作、移动端、agent 市场、多 agent 抢画布、自动发布、老师后台。

## 12. 需要拍板的 6 件事（未回复按默认执行）

1. **默认入口**：一个常驻对话条（底部）+ agent 直接在画布上动手；vs 先选模式再对话。默认前者。
2. **幽灵预览默认开还是关**：默认开（学生强制开）。
3. **内置 agent 还是"只做 MCP server 给外部 agent"**：默认两者都做，内置先做最小版（一个模型 + 一套工具）。
4. **学生模式是否默认禁联网**：默认禁，需显式开。
5. **卡片类型优先级**：默认"闪卡/测验"与"版本对比"进 P1，其余 P2 押后。
6. **隐私口径**：默认"云端只发必要片段 + 不上传附件全文"，本地模型作为可选加速项。
